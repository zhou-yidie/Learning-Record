### 剩余步骤与实现要点（按流水线展开）

- **尺寸归一（缩放到固定大小，如 32×32）**
  - 目的：让后续 DCT 有固定输入，便于取同一频段。
  - 要点：
    - 插值：优先 Bicubic/Lanczos；避免最近邻。
    - 长宽比：推荐中心裁剪成正方形再缩放；若等比缩放+填充，尽量在取低频前裁掉显著边框。
    - 类型：转换为 float32，像素范围 0–255 或 0–1 都可，但要全流程一致。

- **2D DCT（离散余弦变换，类型 II，正交化）**
  - 实现：先对列做 1D DCT，再对行做 1D DCT（分离实现，`norm="ortho"`）。
  - 精度：float32 足够；确保库的 DCT类型和规范一致（OpenCV/FFTpack/fftw 配置一致）。
  - 直觉：低频系数表示大尺度明暗结构，高频表示边缘/噪声/纹理。

- **截取左上角低频子块（如 8×8），处理 DC**
  - 子块：从频谱左上角取连续的最低频区域（8×8 → 64 个系数）。
  - DC 分量 `C(0,0)`：是全局平均亮度。
    - 常做法：将其从“阈值统计集合”里排除（不参与计算中位数），但该位仍参与二值比较。
    - 也可直接丢弃该位（得到 63 位）再补一位别处，工程上两者差异很小。

- **中位数二值化（稳健阈值）**
  - 集合：对低频块（通常排除 DC）的全部系数求中位数 `m`。
  - 规则：`bit(u,v) = 1 if C(u,v) > m else 0`（注意 DCT 系数带符号，阈值自然处理正负）。
  - 为什么中位数：比均值更抗极端值（如强噪声/高亮块），使比特稳定。
  - 位序：固定行优先或列优先顺序，查询与建库必须一致。

- **打包为整数/字节串（便于汉明距离）**
  - 常用：将 64 个比特按位序打成一个 `uint64`（或 8 字节数组）。
  - 小示例（行优先，跳过 DC 参与阈值但仍产生位）：
    - 遍历 8×8，`hash = (hash << 1) | bit`。
  - 更大哈希：16×16 → 256 位，用 4×`uint64` 或 32 字节。

- **相似度计算（汉明距离）**
  - 整数形式：`dist = popcount(hashA ^ hashB)`（按 64 位块分别 popcount 再求和）。
  - 归一化距离（可选）：`dist_norm = dist / L`，便于跨位数比较（L 为位数）。
  - 多旋转稳健性（可选）：对 `0/90/180/270°` 生成多个哈希，取最小距离。

- **阈值选择（经验 → 标定）**
  - 64 位经验阈值：≤5 极似，6–10 相似，11–15 边缘，>15 基本不同。
  - 标定流程：用标注对（同图变体/不同图）→ 扫阈值 → 画 ROC/PR → 选 F1 最大或业务目标点。
  - 位数变化：阈值大致随位数线性放宽（64→256 位，阈值约×4），再用数据微调。

### 关键工程注意

- 一致性：EXIF 方向先矫正；全流程尺寸、插值、DCT规范固定不变。
- 裁剪/边框：尽量先中心裁剪成方形，或在频域前去掉明显边框区域。
- 数值稳定：确保没有 NaN/Inf；DCT 输入用 float32，`norm="ortho"` 防止尺度偏移。
- 性能：先做缩放再 DCT；批量检索时用分桶/倒排或按前缀比特分段粗筛后精算。

## aHash（平均哈希）算法流程

### 1. **预处理阶段**
- **灰度化**：RGB → 单通道亮度（如 BT.601: 0.299R+0.587G+0.114B）
- **尺寸归一**：缩放到固定尺寸（如 8×8），使用 Bicubic 插值
- **中心裁剪**：先裁剪成正方形，再缩放（避免拉伸变形）

### 2. **均值计算**
- **输入**：8×8 灰度矩阵（64 个像素值）
- **计算**：`mean = sum(pixels) / 64`
- **目的**：获得全局平均亮度作为阈值基准

### 3. **二值化**
- **规则**：`bit(i,j) = 1 if pixel(i,j) > mean else 0`
- **结果**：8×8 的二进制矩阵
- **特征**：编码相对亮暗模式，而非绝对亮度值

### 4. **打包输出**
- **位序**：行优先扫描（左上→右下）
- **输出**：64 位哈希值
- **特点**：简单快速，但对光照变化敏感

## dHash（差值哈希）算法流程

### 1. **预处理阶段**
- **灰度化**：同 aHash
- **尺寸设置**：
  - **水平 dHash**：缩放到 9×8（宽比高大 1）
  - **垂直 dHash**：缩放到 8×9（高比宽大 1）

### 2. **相邻比较**
- **水平 dHash**：
  - 对每行：比较相邻列 `diff(i,j) = pixel(i,j+1) - pixel(i,j)`
  - 二值化：`bit(i,j) = 1 if diff(i,j) > 0 else 0`
  - 输出：8×8 = 64 位哈希

- **垂直 dHash**：
  - 对每列：比较相邻行 `diff(i,j) = pixel(i+1,j) - pixel(i,j)`
  - 二值化：`bit(i,j) = 1 if diff(i,j) > 0 else 0`
  - 输出：8×8 = 64 位哈希

### 3. **特征提取**
- **梯度方向**：编码水平/垂直方向的亮度变化趋势
- **边缘信息**：捕获图像中的边缘和纹理方向
- **相对关系**：基于相邻像素的比较，对整体亮度偏移更鲁棒

### 4. **打包输出**
- **位序**：行优先扫描
- **输出**：64 位哈希值
- **特点**：对亮度变化更稳定，但对大旋转敏感

## 算法对比总结

| 特征 | aHash | dHash | pHash |
|------|-------|-------|-------|
| **复杂度** | 最低 | 低 | 中等 |
| **速度** | 最快 | 快 | 较慢 |
| **鲁棒性** | 最弱 | 中等 | 最强 |
| **光照敏感** | 高 | 低 | 低 |
| **压缩鲁棒** | 弱 | 中等 | 强 |
| **特征类型** | 全局亮度模式 | 局部梯度方向 | 低频结构能量 |

## 实际应用建议

- **aHash**：适合快速去重，对光照一致的数据集
- **dHash**：适合一般相似检索，对亮度变化有容忍度
- **pHash**：适合高质量相似检测，对压缩/模糊有鲁棒性
- **组合使用**：多哈希投票可提升整体准确率

这就是为什么你的测试中，不同算法对同一对图片会产生不同汉明距离的原因——它们提取的特征类型和鲁棒性不同。


### 低频能量结构是什么

**低频能量结构**指的是图像在频域中**低频分量（低空间频率）的能量分布模式**，它编码了图像的整体形状、明暗分布和大尺度纹理特征。

#### 1. **空间频率的概念**
- **低频**：变化缓慢的区域，代表整体明暗趋势、大块区域
- **高频**：变化快速的区域，代表边缘、细节、噪声
- **DCT 变换**：将空间域图像分解为不同频率的余弦基函数组合

#### 2. **低频能量结构的具体内容**

**整体形状轮廓**
- 图像的主要几何结构（圆形、方形、三角形等）
- 大块区域的分布（天空、地面、主体物体）
- 整体明暗分布模式

**大尺度纹理**
- 水平/垂直方向的渐变趋势
- 大块区域的纹理方向性
- 整体对比度分布

**感知不变特征**
- 去除细节后的主要结构信息
- 相对亮度关系（而非绝对亮度值）
- 与分辨率无关的形状特征

#### 3. **为什么低频能量结构重要**

**鲁棒性强**
- 对轻微压缩、模糊、噪声相对稳定
- 对光照变化、对比度调整不敏感
- 对轻微几何变换（小角度旋转、轻微缩放）保持稳定

**感知相关性**
- 人眼主要关注整体结构和形状
- 低频信息决定"这张图看起来像什么"
- 细节（高频）对相似性判断影响较小

#### 4. **在 pHash 中的体现**

**DCT 低频块**
```
[[DC, 低频AC, 低频AC, ...],
 [低频AC, 低频AC, 低频AC, ...],
 [低频AC, 低频AC, 低频AC, ...],
 ...]
```

**能量分布**
- **DC 分量**：全局平均亮度
- **低频 AC**：整体明暗分布、大尺度纹理
- **中频 AC**：中等尺度的结构特征
- **高频 AC**：细节、边缘、噪声

**二值化编码**
- 通过中位数阈值，将连续的能量分布转换为离散的 0/1 模式
- 保留相对能量关系，去除绝对数值影响
- 形成稳定的二进制特征向量

#### 5. **实际例子**

**相同内容的轻微编辑**
- 原图：低频能量结构保持稳定 → 哈希相似
- 轻微压缩：低频几乎不变 → 哈希相似
- 亮度调整：低频相对关系不变 → 哈希相似

**不同内容**
- 结构完全不同：低频能量分布差异大 → 哈希差异大
- 主体改变：低频模式改变 → 哈希差异大

这就是为什么 pHash 比其他算法更鲁棒的原因——它专注于提取"人眼感知中最重要的低频能量结构"，而忽略容易变化的细节和噪声。
